1、介绍一下从0到1，你是怎么搭建项目的

**回答思路（按时间线 + 分层说）：**

- **需求与范围**：先明确是全新 App 还是已有业务从 0 搭一版。说清楚目标用户、核心功能、首版要上的模块（例如：登录、首页、若干业务 Tab），以及是否要考虑后续组件化/多端复用。
- **技术选型**：语言（Swift/OC）、最低系统版本、包管理（CocoaPods / SPM）。网络层选型（如 Alamofire + Moya 做请求封装和业务隔离）。若用 Swift，可提 R.swift 做资源类型安全、RxSwift 做响应式（如你笔记里用的）。
- **工程结构**：按层或按业务划分目录。常见做法：
  - **按层**：UI 层（VC/View/ViewModel）、网络层（API、请求封装）、数据层（本地 DB/缓存，如 GRDB）、通用层（扩展、工具、基类）。
  - **按模块**：登录、首页、设置等各自一个模块，模块内再分 UI/网络/数据。
- **基础能力**：AppDelegate/SceneDelegate 里做统一入口：初始化网络、日志、崩溃收集、路由/组件化入口（若用 Target-Action 或 URL 路由）。统一导航栏、主题、埋点等。
- **规范与协作**：命名规范、目录规范、Code Review；接口文档与 Mock；CI（打包、单元测试）若有的可以简单提。
- **收尾**：首版上线后如何做启动优化、包体积、崩溃监控等，说明你会考虑「可扩展、可维护」。

**简版口述示例（1 分钟内）：**  
“从 0 到 1 我会先定需求范围和首版功能，然后做技术选型，比如 Swift + CocoaPods，网络用 Alamofire+Moya。工程上按 UI 层、网络层、数据层来分，必要时再按业务模块划目录。在 AppDelegate 里统一做网络、日志、路由等初始化，并约定好命名和目录规范。上线后会关注启动、包体积和可维护性。”
